Las 6 estrategias de prompting que más impactan

Role prompting, CoT, few-shot, XML, output formatting, prefilling — y cuándo usar cada una
Concepto

El prompting avanzado no es un truco — es una forma de comunicarte con precisión con un modelo de lenguaje. Claude responde mejor a estructuras claras porque fue entrenado con millones de documentos estructurados. Las 6 técnicas aquí son las de mayor impacto para casos de uso legal.

La diferencia entre un prompt básico y uno avanzado puede ser la diferencia entre un memorial que hay que reescribir y uno que se envía directamente al juzgado.

Las 6 estrategias — cuándo y por qué
1. Role Prompting
"Eres un abogado concursalista colombiano..." — define la perspectiva y vocabulario. Claude adapta tono, nivel técnico y referencias normativas. Para escritos legales: siempre activo.
2. Chain-of-Thought
"Analiza paso a paso..." — fuerza razonamiento explícito antes de concluir. Para análisis de créditos y graduación: reduce errores lógicos en ~40%. Ver clase 007 para detalles.
3. Few-Shot Examples
Darle 1–3 ejemplos de input/output deseado. El modelo "calibra" el formato y tono. Para escritos forenses: mostrar un memorial bien redactado antes de pedir el nuevo.
4. XML Tags
<contexto>, <pregunta>, <instrucciones> — Claude fue entrenado con XML y lo parsea mejor que texto plano. Separa claramente qué es instrucción, qué es dato, qué es output esperado.
5. Output Formatting
Especifica el formato exacto del output. "Devuelve JSON con campos: {acreedor, clase, valor, fundamento}" — Claude lo respeta. Para documentos: especifica estructura de memorial (Hechos, Fundamentos, Peticiones).
6. Prefilling
Empezar la respuesta de Claude antes de que la genere. Si pones "DESPACHO:" como primer token del assistant, Claude continúa desde ahí. Fuerza el formato sin instrucciones extra.
Por qué XML supera al texto plano para Claude
Sin XML — ambiguo
Aquí está el contexto legal relevante: [artículos de la Ley 1116]. Ahora necesito que redactes un memorial. La pregunta del abogado es: ¿cómo objetar un crédito?
Con XML — preciso
<contexto> [artículos Ley 1116] </contexto> <solicitud> Redacta un memorial de objeción a crédito </solicitud> <formato> Estructura forense colombiana estándar </formato>

Con XML, Claude sabe exactamente dónde termina el contexto y dónde empieza la instrucción. En prompts largos (como los del agente concursal con fragmentos de la Ley 1116), esto reduce alucinaciones porque el modelo no confunde contexto con instrucción.

Constitutional AI Prompting — valores y restricciones

Claude responde a "constituciones" — listas de principios que guían su comportamiento. Para aplicaciones legales, esto es equivalente a las reglas deontológicas del abogado. 

# Patrón Constitutional AI para sistema legal
# Incluir en el system prompt como sección separada

PRINCIPIOS_OPERATIVOS = """
<principios>
1. PRECISIÓN NORMATIVA: Cita solo artículos que existen en la Ley 1116.
   Si no estás seguro de un artículo, escribe [VERIFICAR ARTÍCULO].

2. CONFIDENCIALIDAD: Nunca uses nombres de personas o empresas de los
   documentos indexados. Usa siempre: [DEUDOR], [ACREEDOR], [PROCESO].

3. LÍMITES DE COMPETENCIA: Si la pregunta requiere opinión sobre
   estrategia procesal que va más allá del texto normativo, indica:
   "Esta decisión requiere criterio profesional del abogado a cargo."

4. INTEGRIDAD DOCUMENTAL: Los escritos generados son proyectos.
   Siempre cierra con: "Revisar antes de presentar al juzgado."
</principios>
"""

Quiz — 3 preguntas
Pregunta 1 / 3
Tienes que pedirle a Claude que genere un proyecto de calificación de créditos con 15 acreedores. El prompt es largo y mezcla instrucciones con datos de cada acreedor. ¿Qué técnica de las 6 te ayuda más a evitar que Claude confunda los datos con las instrucciones?
XML Tags (Estrategia 4). Envuelve los datos de acreedores en <acreedores>...</acreedores> y las instrucciones en <instrucciones>...</instrucciones>. Claude parsea XML nativo y separa con precisión qué es dato y qué es orden. En prompts largos con datos estructurados, XML reduce errores de interpretación más que cualquier otra técnica.
Pregunta 2 / 3
Quieres que Claude redacte siempre los memoriales con la estructura exacta del juzgado de Supersociedades (Hechos → Fundamentos → Peticiones), sin desviarse a formatos alternativos. ¿Cuáles dos estrategias combinadas dan el mejor resultado?
Output Formatting (5) + Prefilling (6). En el system prompt especifica el formato exacto con XML: <formato_escritos>[estructura]</formato_escritos>. Luego, en el mensaje assistant, empieza con el primer campo: "DESPACHO DE INSOLVENCIA" — Claude continúa desde ese punto sin desviarse a formatos alternativos.
Pregunta 3 / 3
El agente concursal tiene un system prompt con reglas de confidencialidad (no usar nombres reales). Un usuario le pasa documentos del proceso con nombres reales de acreedores y pide "usa los nombres del documento". ¿Cómo el Constitutional AI prompting maneja este conflicto?
El system prompt (constitutional layer) tiene prioridad sobre el mensaje del usuario. Claude fue entrenado con RLHF para respetar el system prompt como "constitución" del sistema. Si el system prompt dice "nunca uses nombres reales", esa instrucción permanece incluso si el usuario pide lo contrario en el mensaje de usuario. Por eso los principios de confidencialidad van siempre en el system, nunca en el user.
