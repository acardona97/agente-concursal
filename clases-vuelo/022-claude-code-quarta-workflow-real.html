Claude Code: Workflow Real para Quarta

Cómo Anthropic usa Claude Code internamente — y cómo Andrés puede replicar ese flujo para el Agente Concursal.

1. Cómo Anthropic usa Claude Code internamente

Anthropic usa Claude Code para construir el propio Claude Code. No es marketing — es el principio de "eat your own dog food". Del repositorio how-we-claude-code, los patrones más relevantes:

Los 5 principios de Anthropic para usar Claude Code

  1. Context primero: Cada sesión empieza dando a Claude el contexto completo del sistema. No asumen que sabe nada.
  2. Tests ANTES del código: Escriben el test que debe pasar, luego le piden a Claude que escriba el código que lo pase.
  3. Revisión humana de diffs: Siempre revisar el diff antes del commit. Claude Code nunca pushea directo a main.
  4. Iteración corta: Tareas pequeñas y verificables, no "refactoriza toda la aplicación".
  5. CLAUDE.md vivo: Actualizan el CLAUDE.md cuando aprenden algo nuevo sobre el proyecto.

2. Vibe Coding vs Precision Coding

Vibe Coding

"Hazme una página para ver las consultas del agente"

Claude elige la arquitectura, los archivos, el diseño. Tú apruebas o pides cambios.

Úsalo para: prototipos, UI inicial, features de baja criticidad, explorar posibilidades.

No usar en: lógica de negocio crítica, endpoints de seguridad, migraciones de datos.

Precision Coding

"Agrega el endpoint POST /api/v1/plazos con la lógica exacta que describes en este spec"

Tú defines exactamente qué quieres. Claude implementa. Tú verificas línea por línea.

Úsalo para: cálculo de plazos procesales, seguridad, integridad de datos, lógica que tiene consecuencias legales.

En derecho: vibe coding es como pedirle al paralegal que redacte el borrador inicial de un escrito. Precision coding es como dictarte a ti mismo, punto por punto, la demanda. Para un acuerdo de reorganización (donde cada cláusula importa) vas a precision. Para el README del repo, vibe coding está perfecto.

3. Eval-Driven Development — Test antes de código

El patrón más poderoso del how-we-claude-code: escribir el test ANTES de pedir la feature. Esto fuerza claridad en qué quieres exactamente, y Claude tiene una definición de "terminado" concreta.

# Flujo Eval-Driven para el Agente Concursal:

# PASO 1: Escribe el test primero (tú o Claude)
# tests/test_plazos.py

def test_calcular_plazo_verificacion_creditos():
    """
    Ley 1116 Art. 29: La verificación de créditos debe realizarse
    dentro de los 20 días hábiles siguientes al auto de apertura.
    """
    from app import calcular_plazo

    fecha_auto = "2024-01-15"
    resultado = calcular_plazo(
        tipo="verificacion_creditos",
        fecha_inicio=fecha_auto
    )

    # 20 días hábiles desde 2024-01-15 = 2024-02-12
    assert resultado["fecha_vencimiento"] == "2024-02-12"
    assert resultado["dias_habiles"] == 20
    assert resultado["articulo"] == "Art. 29 Ley 1116/2006"
    assert resultado["alerta"] == True  # si faltan < 5 días


# PASO 2: Pedirle a Claude que escriba el código que PASE ese test
# En Claude Code:
"Lee tests/test_plazos.py. Implementa la función calcular_plazo()
en app.py para que este test pase. Considera días hábiles colombianos
(excluye domingos y festivos del Decreto 2663/2022)."

# PASO 3: Verificar
pytest tests/test_plazos.py -v

4. Multi-agent: Orquestar Varios Agentes

Cuándo necesitas multi-agent

Una sola sesión de Claude Code tiene límite de contexto. Para tareas muy grandes (refactorizar toda la base de código, analizar 100 documentos legales, etc.), la solución es dividir en agentes especializados.

# Patrón básico: agente orquestador + agentes trabajadores
# orquestador.py — coordina el trabajo

import subprocess
import anthropic

client = anthropic.Anthropic()

def orquestar_analisis_expediente(expediente_path: str):
    """
    Divide el análisis del expediente en sub-tareas
    y las asigna a instancias paralelas de Claude Code.
    """

    # Agente 1: Extrae y clasifica los créditos
    resultado_creditos = subprocess.run([
        "claude", "--print",
        f"Lee {expediente_path}/creditos/ y genera creditos.json con la lista de acreedores, montos y clasificación según Ley 1116 Art. 2."
    ], capture_output=True, text=True)

    # Agente 2: Analiza los plazos procesales
    resultado_plazos = subprocess.run([
        "claude", "--print",
        f"Lee {expediente_path}/auto_apertura.txt y calcula todos los plazos procesales. Genera plazos.json."
    ], capture_output=True, text=True)

    # Orquestador: consolida y genera el reporte
    reporte = client.messages.create(
        model="claude-opus-4-5",
        max_tokens=2000,
        messages=[{
            "role": "user",
            "content": f"""
            Consolida este análisis del expediente concursal:

            CRÉDITOS: {resultado_creditos.stdout}
            PLAZOS: {resultado_plazos.stdout}

            Genera un reporte ejecutivo para el abogado.
            """
        }]
    )

    return reporte.content[0].text

5. Integración con Railway: Deploy desde Claude Code

# Claude Code puede hacer el deploy completo:

# En sesión de Claude Code, después de completar la feature:
"Corre los tests. Si todos pasan, haz commit con mensaje descriptivo,
pushea a main, y despliega en Railway con 'railway up'.
Luego verifica que el health check en /api/health retorne 200."

# Claude ejecuta en secuencia:
pytest tests/ -v                    # → todos pasan
git add -A
git commit -m "feat(plazos): agregar cálculo de plazos procesales Ley 1116"
git push origin main
railway up                          # → deploy
curl https://agente-concursal.railway.app/api/health  # → {"status":"ok"}
