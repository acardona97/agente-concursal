Fine-tuning vs Prompting — la decisión que Quarta ya tomó

Calibración · Por qué para derecho concursal colombiano siempre gana el prompting
Concepto

Fine-tuning: tomar un modelo base y re-entrenarlo con miles de ejemplos específicos de tu dominio. El modelo "aprende" ese dominio en sus pesos — pero queda congelado en el tiempo del entrenamiento.

Prompting: darle instrucciones, contexto y ejemplos al modelo en el momento de cada consulta. El modelo no cambia, pero su comportamiento sí — de forma inmediata, flexible y sin costo de entrenamiento.

Para casos como Quarta, el prompting con RAG es superior en casi todas las dimensiones que importan: costo, velocidad de actualización, control sobre el output, y capacidad de razonamiento en temas no vistos durante entrenamiento.

Fine-tuning es contratar un abogado especialista exclusivo que solo sabe de concursal colombiano — perfecto para eso, inútil para cualquier otra cosa, y tardó 3 años formándose. Prompting es darle instrucciones detalladas a un abogado generalista brillante (Claude) antes de cada consulta — se adapta en tiempo real, puede actualizar su conocimiento hoy si sale un nuevo decreto, y puedes redirigirlo a otro tema mañana.
Comparación directa

Fine-tuning

  • Requiere 1,000+ ejemplos etiquetados
  • Costo: $500–$5,000 por entrenamiento
  • Tiempo: días o semanas
  • Actualizar jurisprudencia = re-entrenar
  • Conocimiento queda "congelado"
  • No puede razonar fuera del dominio
  • Difícil de depurar errores

Prompting + RAG

  • Empieza con 0 ejemplos adicionales
  • Costo: solo tokens por consulta
  • Cambios en tiempo real
  • Actualizar = cambiar prompt o base vectorial
  • Contexto fresco en cada consulta
  • Claude puede razonar por analogía legal
  • Errores visibles en el prompt
Veredicto para Quarta
"Para derecho concursal colombiano: siempre prompting. Fine-tuning no aplica hoy."
Cuándo fine-tuning SÍ tiene sentido (no es tu caso)
Fine-tuning vale la pena SOLO si: ────────────────────────────────── ✓ Tienes 10,000+ ejemplos de alta calidad etiquetados ✓ El formato de output es muy específico y repetitivo (ej: extraer campos estructurados de formularios industriales) ✓ Latencia ultra-baja es crítica (modelo más pequeño afinado) ✓ El dominio NO cambia (física, matemáticas puras) ✓ Privacidad extrema requiere modelo on-premise Para Quarta específicamente: ────────────────────────────── ✗ La Ley 1116 se interpreta con jurisprudencia que cambia ✗ Cada proceso tiene hechos únicos que requieren razonamiento ✗ Los decretos de emergencia (ej: Decreto 772/2020) se actualizan ✗ No tienes 10,000 ejemplos de escritos concursales etiquetados ✗ El razonamiento analógico (un caso nuevo = aplicar principio viejo) requiere capacidad de generalización que el fine-tuning no da
Regla práctica: antes de considerar fine-tuning, pregúntate: "¿He agotado todas las técnicas de prompting?" La respuesta suele ser no. Las clases 006–011 te dan el 90% del valor que buscarías en fine-tuning, sin ningún costo de entrenamiento.
Quarta — la estrategia correcta

Tu agente concursal ya está en el camino correcto: prompting + RAG. El SYSTEM_PROMPT en agente.py es sofisticado — define rol, reglas de redacción, guardrails de confidencialidad, y formato de output.

Lo que falta no es fine-tuning — son técnicas avanzadas de prompting que verás en el Bloque 1: XML tags para estructurar el contexto, chain-of-thought para análisis de créditos complejos, few-shot examples para redacción forense, y prompt caching para que la Ley 1116 no se re-embeba en cada consulta.

Esas técnicas son la diferencia entre un sistema que "funciona" y uno que "impresiona a cualquier juez de concurso".

En la clase 006 aplicamos esto eligiendo la estrategia correcta de prompting — y reescribimos el system prompt del agente concursal con las 6 técnicas que más impactan.
