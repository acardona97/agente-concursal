System Prompts que funcionan — anatomía y playbook

Cómo Claude lee el system prompt — y el template completo para el Quarta Legal Hub
Concepto

El system prompt no es "texto que Claude lee". Es la constitución de tu aplicación: define quién es Claude en este contexto, qué puede hacer, qué no puede, cómo debe formatear las respuestas, y qué hacer cuando el usuario pide algo fuera del alcance.

Claude fue entrenado para darle prioridad al system prompt sobre el mensaje del usuario. Eso significa que tus reglas de confidencialidad, formato y guardrails legales son innegociables — el usuario no puede saltárselas con instrucciones en el chat.

Un system prompt bien construido tiene 5 secciones. Omitir alguna crea ambigüedad que Claude resuelve con su criterio propio, que puede diferir del tuyo.

Anatomía de un system prompt poderoso — 5 secciones
1. IDENTIDAD
Quién es Claude. Rol específico, experiencia, perspectiva. "Eres un agente jurídico especializado en..." — no "eres un asistente útil".
2. CAPACIDADES
Qué sabe hacer y qué herramientas tiene. Lista explícita de tareas que puede ejecutar. Ayuda a Claude a decidir si una solicitud está dentro de su alcance.
3. RESTRICCIONES
Qué NO debe hacer y por qué. Guardrails: confidencialidad, precisión, límites de competencia. Las restricciones siempre van en el system, nunca en el user.
4. FORMATO
Cómo debe estructurar las respuestas. Estructura de memoriales, cuándo usar markdown, cuándo usar texto plano, idioma, nivel de formalidad.
5. EJEMPLOS
1–2 ejemplos de input/output ideal (few-shot en el system prompt). Para escritos forenses: un memorial de objeción bien redactado como referencia de calidad.
Estructura implícita: Claude no solo lee el texto del system prompt — "entiende" su jerarquía. Identidad → Capacidades → Restricciones es el orden que más reduce comportamientos inesperados. Invertir el orden (restricciones primero) puede generar un Claude más defensivo de lo necesario.
Guardrails legales — cuándo Claude no debe responder

En aplicaciones legales, hay situaciones donde Claude debe negarse a responder o escalar al abogado. El pattern del repositorio claude-for-legal: 

# Patrón de guardrails legales — incluir en <restricciones> del system prompt

GUARDRAILS_LEGALES = """
<restricciones>
CUÁNDO RESPONDER con información legal:
- Consultas sobre Ley 1116, Decreto 772, jurisprudencia concursal colombiana ✓
- Redacción de escritos con base en hechos que el abogado proporciona ✓
- Análisis de graduación y calificación de créditos ✓

CUÁNDO ESCALAR al abogado (responde con aviso explícito):
- Estrategia procesal que implica juicio sobre probabilidades de éxito
  → Respuesta: "Esta decisión implica valoración estratégica que corresponde
    al abogado a cargo del proceso."
- Predicciones sobre decisiones judiciales futuras
  → Respuesta: "No puedo predecir decisiones judiciales. El análisis jurídico
    indica [X], pero la decisión final es del juez."
- Conflictos de interés potenciales detectados en el caso
  → Respuesta: "Identifiqué un posible conflicto de interés en [X]. El abogado
    debe evaluar esto antes de continuar."

CUÁNDO NEGARSE a responder:
- Solicitudes de usar información de otros clientes del contexto indexado
  → "No puedo usar información de otros procesos. La consulta debe basarse
    en los hechos que me proporcionas."
- Solicitudes de afirmar hechos que no están en el contexto proporcionado
  → "No tengo información sobre [X] en el contexto actual. Proporciona
    los documentos relevantes para responder con precisión."
</restricciones>
"""

Quiz — 3 preguntas
Pregunta 1 / 3
Un abogado quiere que Claude responda preguntas de derecho laboral y concursal en el mismo agente. ¿Es mejor tener un solo system prompt con ambas capacidades, o dos agentes separados? ¿Por qué?
Depende del volumen, pero para Quarta: dos agentes separados. Un solo system prompt con dos especialidades crea ambigüedad de identidad — Claude puede mezclar marcos normativos. Para Quarta, cuyo diferencial es la profundidad en concursal, un agente con identidad enfocada produce mejor calidad que uno generalista. Si el volumen laboral justifica el costo, el segundo agente tiene su propio system prompt, su propia base RAG (jurisprudencia laboral), y sus propios guardrails (no mezclar créditos laborales concursales con Código Sustantivo).
Pregunta 2 / 3
El system prompt de tu agente concursal actual no tiene la sección "5. Ejemplos" (few-shot). ¿Para qué tipo de tarea sería más valioso agregar un ejemplo en el system prompt?
Para el formato de los escritos procesales. Las reglas de formato en texto (HECHOS numerados, PETICIONES en infinitivo, etc.) son ambiguas sin ver un ejemplo. Agregar un memorial de objeción bien redactado en el system prompt le da a Claude un "nivel de calidad" concreto y un formato visual que puede imitar. Esto es más efectivo que describir el formato en palabras. El ejemplo debe ser representativo del 80% de los casos, con los campos críticos correctamente formateados y [PLACEHOLDERS] donde van los datos reales.
Pregunta 3 / 3
¿Por qué las restricciones de confidencialidad deben estar en el system prompt y no en el user message, incluso si el usuario es el propio abogado?
Por jerarquía del protocolo y protección contra errores humanos. Claude trata el system prompt como instrucciones del operador (Quarta), con mayor prioridad que los mensajes del usuario. Si las restricciones estuvieran en el user message, cualquier nueva conversación podría olvidarlas. Además, incluso el propio abogado puede pedir involuntariamente algo que viole la confidencialidad ("usa los datos del proceso de Bancolombia del mes pasado") — el system prompt actúa como red de seguridad automática que no depende de que el abogado recuerde las reglas en cada sesión.
