Hooks y Automatización en Claude Code

Enseñarle a Claude qué hacer antes y después de cada acción. Automatización sin código complejo.

1. Qué son los Hooks (y qué NO son)

Primero, limpiemos la confusión: los hooks de Claude Code no tienen nada que ver con los webhooks HTTP. No hay URLs, no hay POST requests, no hay servidores escuchando.

Los hooks de Claude Code son como los protocolos de tu firma: "Antes de enviar cualquier escrito, revisar ortografía". "Después de firmar un contrato, archivar copia en el sistema". "Si alguien pide acceso al expediente confidencial, pedir autorización del socio". No son eventos externos — son reglas internas que se ejecutan automáticamente en momentos específicos.

Definición precisa: Los hooks de Claude Code son scripts (Bash o Python) que se ejecutan automáticamente en puntos específicos del flujo de trabajo de Claude. Tú los configuras en settings.json. Claude los respeta siempre.

2. Los 4 Tipos de Hooks

ANTES DE LA ACCIÓN

PreToolUse

Se ejecuta ANTES de que Claude use una herramienta. Puede bloquear la acción si retorna código de error.

Casos: validar antes de escribir, confirmar antes de borrar, revisar seguridad

DESPUÉS DE LA ACCIÓN

PostToolUse

Se ejecuta DESPUÉS de que Claude usa una herramienta. Recibe el resultado.

Casos: auto-commit después de escribir, notificación, logging, tests automáticos

CUANDO CLAUDE NOTIFICA

Notification

Se ejecuta cuando Claude quiere enviar una notificación o necesita tu atención.

Casos: enviar a Slack, beep sonoro, notificación desktop

AL TERMINAR

Stop

Se ejecuta cuando Claude termina una tarea completa.

Casos: resumen final, auto-commit, deploy automático, notificación de completado

3. Dónde vive la configuración

# Dos ubicaciones posibles:

# 1. Global (todos tus proyectos):
~/.claude/settings.json

# 2. Solo este proyecto:
.claude/settings.json   # en la raíz del proyecto

# Estructura básica de settings.json con hooks:
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash /path/to/mi-hook-stop.sh"
          }
        ]
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Write",
        "hooks": [
          {
            "type": "command",
            "command": "python3 /path/to/seguridad-hook.py"
          }
        ]
      }
    ]
  }
}

El campo "matcher"

Filtra en qué herramienta se activa el hook:

  • "" (vacío) → aplica a TODAS las herramientas
  • "Write" → solo cuando Claude escribe archivos
  • "Bash" → solo cuando Claude ejecuta comandos
  • "Read" → solo cuando Claude lee archivos

4. Cómo funciona la comunicación hook ↔ Claude

Los hooks se comunican con Claude a través de stdin/stdout y códigos de salida:

# El hook recibe por stdin (JSON):
{
  "tool_name": "Write",
  "tool_input": {
    "file_path": "chroma_db/index.json",
    "content": "..."
  }
}

# El hook puede responder (stdout JSON):
{
  "decision": "block",           # o "approve"
  "reason": "No tocar chroma_db sin confirmación"
}

# Códigos de salida:
exit 0  → continuar normalmente
exit 1  → mostrar output como información a Claude
exit 2  → BLOQUEAR la acción completamente

5. Hook Completo para Quarta — Auto-commit con mensaje

Este hook se activa al terminar (Stop). Hace auto-commit de todos los cambios con un mensaje descriptivo generado por Claude, y luego envía una notificación por consola.

#!/bin/bash
# Archivo: ~/.claude/hooks/quarta-stop-hook.sh
# Hook tipo: Stop
# Propósito: auto-commit al terminar sesión de Claude Code

set -e

# 1. Leer el input de Claude (JSON con info de la sesión)
INPUT=$(cat)

# 2. Verificar si hay cambios para commitear
if ! git diff --quiet || ! git diff --cached --quiet || \
   [ -n "$(git status --porcelain)" ]; then

  # 3. Obtener lista de archivos modificados
  ARCHIVOS=$(git status --porcelain | head -20)
  TIMESTAMP=$(date '+%Y-%m-%d %H:%M')

  # 4. Generar mensaje de commit descriptivo
  # Extraer el "transcript" o descripción de la sesión si está disponible
  DESCRIPCION=$(echo "$INPUT" | python3 -c "
import json, sys
data = json.load(sys.stdin)
msg = data.get('message', data.get('description', 'Sesión Claude Code'))
print(msg[:100])
  " 2>/dev/null || echo "Sesión Claude Code automatizada")

  # 5. Hacer el commit
  git add -A
  git commit -m "auto(claude-code): $DESCRIPCION

Archivos modificados:
$ARCHIVOS

Timestamp: $TIMESTAMP
[claude-code-hook]" 2>&1

  # 6. Notificación visual en consola
  echo ""
  echo "╔══════════════════════════════════════╗"
  echo "║  QUARTA - Claude Code Session Done   ║"
  echo "╠══════════════════════════════════════╣"
  echo "║  ✓ Auto-commit realizado              ║"
  echo "║  ✓ Timestamp: $TIMESTAMP    ║"
  echo "╚══════════════════════════════════════╝"
  echo ""

  # 7. Opcional: enviar a Telegram (si tienes el bot configurado)
  if [ -n "$TELEGRAM_BOT_TOKEN" ] && [ -n "$TELEGRAM_CHAT_ID" ]; then
    MENSAJE="🤖 Claude Code terminó en agente-concursal%0A✓ Commit: $DESCRIPCION"
    curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/sendMessage" \
      -d "chat_id=$TELEGRAM_CHAT_ID&text=$MENSAJE" > /dev/null
  fi

else
  echo "No hay cambios para commitear."
fi

Hook de Seguridad — Proteger la base vectorial

#!/usr/bin/env python3
# Archivo: ~/.claude/hooks/quarta-seguridad.py
# Hook tipo: PreToolUse (matcher: "Write")
# Propósito: NUNCA dejar que Claude modifique chroma_db/ sin confirmación

import json
import sys
import os

# Directorios y archivos protegidos
PROTEGIDOS = [
    "chroma_db/",
    ".env",
    "railway.toml",
    "requirements.txt"
]

# Leer el input de Claude
try:
    data = json.load(sys.stdin)
except:
    sys.exit(0)  # Si no hay JSON, dejar pasar

# Obtener la ruta del archivo que Claude quiere modificar
file_path = data.get("tool_input", {}).get("file_path", "")

# Verificar si está en zona protegida
for zona in PROTEGIDOS:
    if zona in file_path or file_path.endswith(zona.strip("/")):

        # Bloquear y explicar
        respuesta = {
            "decision": "block",
            "reason": (
                f"SEGURIDAD: '{file_path}' está en zona protegida ({zona}). "
                f"Para modificar esta zona, Andrés debe confirmar explícitamente: "
                f"'Confirmo modificar {zona}'"
            )
        }
        print(json.dumps(respuesta))
        sys.exit(2)  # Código 2 = BLOQUEAR

# Si no es zona protegida, aprobar
sys.exit(0)

6. Los 5 Hooks más útiles para el Workflow de Quarta

  • Auto-commit al terminar
    Tipo: Stop. Nunca perder trabajo por cerrar la sesión sin commitear. El más importante para un developer solitario.
  • Protección de la base vectorial (chroma_db/)
    Tipo: PreToolUse(Write). Los documentos de la Ley 1116 y jurisprudencia son irreemplazables. Una barrera de seguridad vale oro.
  • Auto-test después de cambiar app.py
    Tipo: PostToolUse(Write). Cada vez que Claude modifica app.py, correr pytest automáticamente. Detectar regresiones al instante.
  • Notificación en el teléfono al terminar tarea larga
    Tipo: Stop. Cuando le pediste a Claude Code refactorizar todo el módulo (tarea de 10 min), recibir un push notification para saber que terminó.
  • Log de sesiones para auditoría
    Tipo: Stop. Guardar en un archivo qué cambió en cada sesión. Como el libro de radicación del despacho: registro de todo lo que pasó.

Hook de auto-test (PostToolUse)

#!/bin/bash
# Archivo: ~/.claude/hooks/quarta-autotest.sh
# Se activa cuando Claude modifica archivos .py

INPUT=$(cat)
FILE=$(echo "$INPUT" | python3 -c "
import json, sys
d = json.load(sys.stdin)
print(d.get('tool_input',{}).get('file_path',''))
" 2>/dev/null)

# Solo correr tests si modificó un .py de la app
if [[ "$FILE" == *.py ]] && [[ "$FILE" != tests/* ]]; then
  echo "Corriendo tests por modificación en $FILE..."
  cd /home/user/agente-concursal
  python -m pytest tests/ -x -q 2>&1 | tail -10
fi
