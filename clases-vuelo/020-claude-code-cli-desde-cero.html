Claude Code CLI desde Cero

Del chat a la terminal. Por qué el abogado-desarrollador que construyó el Agente Concursal necesita esto.

1. Qué hace Claude Code que el chat NO hace

El chat de Claude.ai es como un asesor legal por teléfono: te da respuestas, te explica, pero no puede abrir tu escritorio, leer tus contratos, ni firmar documentos. Claude Code CLI es ese mismo asesor sentado en tu oficina, con acceso a todos tus archivos.

El chat de Claude es como consultar a un colega abogado por WhatsApp. Claude Code es ese mismo colega que viene a tu oficina, lee todos tus expedientes, ejecuta acciones y te pide confirmación solo cuando algo es irreversible. Misma inteligencia. Diferente nivel de acceso.

Lo que SOLO hace Claude Code

  • Lee y escribe archivos reales — no copia/pega, modifica directamente
  • Ejecuta comandos en tu terminal — pip install, python app.py, git commit
  • Navega y entiende tu proyecto entero — lee múltiples archivos para entender el contexto
  • Hace git — commits, branches, diffs, sin que toques la terminal
  • Corre tests y ve si pasan — y los arregla si fallan
  • Puede operar en loop sin que tú estés — modo autónomo con --dangerously-skip-permissions

El chat normal hace bien

  • Explicar conceptos, revisar código pegado a mano, ayudar a pensar arquitectura, redactar documentos

Para Quarta: usa el chat para redactar demandas y estrategia. Usa Claude Code para construir el software.

2. Instalación en 60 segundos

# Requisito: Node.js >= 18
node --version   # debe ser v18+ 

# Instalar Claude Code globalmente
npm install -g @anthropic-ai/claude-code

# Primera vez: autenticarse
claude

# Abre el browser, autoriza, ya está.
# Para verificar que funciona:
claude --version

4. CLAUDE.md — El archivo más importante

Si hubiera que elegir UNA cosa de esta clase: es el CLAUDE.md. Es el contrato entre tú y Claude Code. Cada vez que abres el CLI en tu proyecto, Claude lee ese archivo ANTES de hacer cualquier cosa. Es como dejarle al paralegal las instrucciones de la firma antes de irse de vacaciones.

CLAUDE.md es como el reglamento interno de tu firma. Cuando entra un nuevo abogado (o Claude en una nueva sesión), lo primero que lee son las políticas: cómo se hacen los escritos, qué no se toca, cuáles son los clientes, qué formato tienen los documentos. Sin ese reglamento, cada sesión empieza desde cero.

CLAUDE.md completo para el Agente Concursal de Quarta

# CLAUDE.md — Agente Concursal · Quarta Legal Hub
# Lee esto PRIMERO. Cada sesión de Claude Code empieza aquí.

## PROYECTO
- Nombre: Agente Concursal
- Dueño: Andrés Cardona (abogado, fundador Quarta)
- Stack: Flask + ChromaDB + Anthropic API + Railway
- Propósito: IA para análisis de procesos de insolvencia bajo Ley 1116 de Colombia

## ARQUITECTURA
- app.py          → Servidor Flask principal, rutas y lógica
- chroma_db/      → Base vectorial (NO modificar sin confirmación explícita)
- documents/      → PDFs y textos de la Ley 1116, jurisprudencia
- prompts/        → Templates de prompts para Claude API
- requirements.txt → Dependencias Python
- railway.toml    → Config de deployment

## REGLAS CRÍTICAS
1. NUNCA modificar chroma_db/ sin preguntar primero
2. NUNCA hacer push a main directamente — siempre rama + PR
3. Los endpoints de Flask van en /api/v1/
4. Toda función debe tener docstring en español
5. Variables de entorno: ANTHROPIC_API_KEY, RAILWAY_TOKEN — NUNCA hardcodear

## CONVENCIONES DE CÓDIGO
- Python: snake_case, PEP8
- Comentarios en español
- Logs con formato: [AGENTE][NIVEL] mensaje
- Tests en /tests/ con pytest
- Error handling: siempre retornar {"error": str, "code": int}

## COMANDOS FRECUENTES
- Desarrollo local: `python app.py`
- Tests: `pytest tests/ -v`
- Deploy: `railway up` (solo desde main)
- Ver logs Railway: `railway logs`

- Procesos: Reorganización y Liquidación Judicial

6. Context Management: /compact, /clear, /plan

Cuándo usar cada uno

ComandoAnalogíaÚsalo cuando
/planPedir al paralegal que te presente el plan de trabajo antes de empezarTarea compleja, riesgo de cambios grandes, primera vez en un módulo
/compactHacer un resumen del expediente — descartas los papeles pero mantienes lo importanteLlevas 1+ hora, el contexto está lleno, Claude empieza a olvidar
/clearCerrar el expediente y abrir uno nuevoCambias de tarea completamente, quieres sesión limpia

El contexto de Claude Code es como la memoria de trabajo de un abogado: puede manejar un caso complejo, pero si acumula demasiados detalles de casos distintos, empieza a confundirse. /compact hace un resumen inteligente para liberar espacio sin perder el hilo.

7. Modos de Operación

Normal Mode (defecto)

Claude pregunta permiso antes de ejecutar acciones importantes (escribir archivos, correr comandos). El balance perfecto para desarrollo diario.

Plan Mode (/plan o --plan)

Claude propone el plan completo ANTES de hacer nada. Lo apruebas o corriges. Luego ejecuta. Ideal para features grandes o cuando eres nuevo en el proyecto.

# Flujo con plan mode:
$ claude --plan "Agregar endpoint para analizar plazos procesales"

# Claude responde:
Plan de ejecución:
1. Crear /api/v1/plazos_procesales en app.py
2. Agregar función analizar_plazo(tipo_proceso, fecha_inicio)
3. Consultar prompts/plazo_template.txt
4. Escribir tests en tests/test_plazos.py

¿Proceder? [y/n]

Autonomous / "Yolo" Mode

Claude ejecuta todo sin pedir permiso. Úsalo en entornos aislados (Docker, VM), CI/CD, o cuando ya confías completamente en las reglas del CLAUDE.md.

# Con flag (NO en producción sin CLAUDE.md robusto):
claude --dangerously-skip-permissions "correr todos los tests y arreglar los que fallen"

Para Quarta: úsalo solo en ambiente de desarrollo, nunca en el servidor de Railway directamente.

8. Permission Modes — Trabajar sin interrupciones

# En settings.json (~/.claude/settings.json):
{
  "permissions": {
    "allow": [
      "Bash(git *)",
      "Bash(pytest *)",
      "Bash(python *)",
      "Write(src/*)",
      "Write(tests/*)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Write(chroma_db/*)",
      "Write(.env)"
    ]
  }
}

# Esto le dice a Claude:
# - Puede hacer git y pytest sin preguntar
# - NUNCA tocar chroma_db/ ni .env
# - Todo lo demás: preguntar
